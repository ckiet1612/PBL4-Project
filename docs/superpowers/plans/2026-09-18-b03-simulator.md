> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan inline task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Do not dispatch implementation subagents, create a branch, commit, push, or change Git history.

**Goal:** Build a deterministic virtual-time simulator, shared pure policy contract, FIFO/RR/WRR/DRR/DRF baselines, reproducible trace fixtures, metrics, raw evidence, and plot/table generation for B03 without implementing the production fairness policy.

**Architecture:** Keep B03 entirely under `benchmarks/` with immutable dataclasses, integer resource/time units, exact rational arithmetic, a stable event queue, and a simulator-owned mutable state. Baselines consume immutable snapshots and return a job choice without I/O or direct state mutation. Canonical JSON traces and results make identical trace/seed/config runs byte-equivalent, while a standard-library report generator derives CSV/SVG comparison artifacts from raw output.

**Tech Stack:** Python 3.12 standard library (`argparse`, `dataclasses`, `enum`, `fractions`, `hashlib`, `heapq`, `json`, `random`, `statistics` where exact semantics are preserved); pytest, Hypothesis, Ruff, `uv` from the existing lockfile.

## Global Constraints

- Preserve `PLAN.md`, B01/B02 behavior, contracts, invariants, acceptance thresholds, and project skills unchanged.
- Create no API, database, migration, Docker, worker, coordinator, product CLI/UI, PyTorch, lease, fence, checkpoint, recovery, production ledger, aging/reservation, or production fairness implementation.
- Keep simulator code pure: no database, network, Docker, PyTorch, sleep, system clock, global random state, or filesystem path supplied by a simulated client.
- Use integer `time_ms`, `cpu_millis`, `memory_bytes`, and whole simulated GPU UUIDs. Use `fractions.Fraction` for every comparison affected by ratios; serialize exact values as canonical numerator/denominator strings.
- Reject negative requests/capacities, non-positive durations, duplicate job/tenant/GPU identifiers, non-positive tenant weights, quota above invalid bounds, and malformed traces before simulation.
- Treat an allocation as held until its completion/release event. Never exceed host capacity, tenant quota, tenant concurrency, or GPU exclusivity.
- Mark requests that can never fit total capacity or their tenant hard quota `INFEASIBLE` with a stable reason. Temporary lack of free capacity leaves the job queued.
- Process equal-time events deterministically by `(time_ms, phase, insertion_sequence)`, with release/completion before arrival and dispatch after all same-time state changes.
- Policy inputs are immutable tuples/mappings and explicit current time. Policies never mutate engine state, read a global clock, or perform I/O.
- All five baselines run the same materialized workload, seed, capacity, quotas, weights, admission rules, completion rules, and release rules.
- Weighted Jain is `x_i = dominant_resource_time_i / weight_i` and `J = (sum(x_i)^2)/(n*sum(x_i^2))`, only for a predeclared window and tenant set verified as continuously demanding and quota-capable.
- Raw deterministic output excludes wall-clock timestamps and wall execution duration. `simulation_runtime_ms` means virtual makespan; command wall time is recorded separately in evidence.
- Do not add a dependency unless the standard library and existing Hypothesis/pytest/Ruff stack cannot meet a requirement. Any dependency change would require an explicit plan revision before editing `pyproject.toml` or `uv.lock`.
- Do not claim ACC-09, ACC-10, ACC-11, PostgreSQL/API throughput, Linux/Docker execution, lease/recovery, or real GPU acceptance from simulator evidence.

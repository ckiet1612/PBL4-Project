# B12 CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with review checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `nexa` product CLI as a secure, bounded REST client for the B12 user and `SYSTEM_ADMIN` command capabilities while preserving the existing `nexa-maintenance` command.

**Architecture:** Typer command modules call a transport-only `NexaClient`. Config/profile and credential storage are independent local modules; output and error mapping are independent presentation modules. All authorization, tenant ownership, state transitions, idempotency records, ETags, quota, and recovery decisions remain in the REST API.

**Tech Stack:** Python 3.12, Typer 0.27, httpx 0.28, Pydantic models already used by the API, TOML from the Python standard library, JSON/atomic filesystem writes, Pytest, Ruff.

**Spec:** `docs/superpowers/specs/2026-09-24-b12-cli-design.md`

## Global Constraints

- Keep `nexa-maintenance`, `nexa-worker`, and `nexa-coordinator` entry points working.
- Product CLI executable is `nexa`; it uses only the REST API and never imports ORM, database, Docker, worker, or domain authorization internals. Commands whose FastAPI route/service is not present remain unregistered until backend integration evidence exists.
- Keep exact scopes: `jobs:read`, `jobs:write`, `artifacts:read`, `artifacts:write`, `tokens:write`, `admin:read`, and `admin:write`; no scope implies another scope.
- Resolve endpoint, profile, and tenant as flag, then environment, then active profile.
- Store config under `$XDG_CONFIG_HOME/nexa` or `~/.config/nexa`, with directory mode `0700`, file mode `0600`, atomic replacement, and no raw token in `config.toml`.
- Never accept a raw token through `--token`; use credentials storage, a dedicated environment variable, or stdin.
- Use `X-Nexa-Tenant-Id`, `Authorization: Bearer`, `Idempotency-Key`, `If-Match`, cursor, page-size, and artifact headers exactly as the OpenAPI contract requires.
- Retry GET/read requests only within bounded limits. Retry mutations only with a stable idempotency key and a replayable body.
- Upload and download in bounded chunks. Download writes a staging file, verifies integrity, fsyncs, and atomically renames.
- `--output human|json` separates successful stdout from diagnostic stderr. Exit codes are 0 and 2 through 10 as defined in `docs/cli.md`.
- Do not implement B15 controls (`cancel`, `pause`, `resume`, manual `retry`, quarantine, or recovery control), scheduler logic, Web UI, GPU, multi-server, load, portability, or release work.
- Do not commit, push, create a branch/worktree, or submit a Task Review request.

**Interfaces:**
- `ConfigStore.load() -> CliConfig`, `ConfigStore.save(config: CliConfig) -> None`, `ConfigStore.save_token(profile: str, token: str) -> None`, and `ConfigStore.get_token(profile: str) -> str | None` provide local config and credential persistence.
- `resolve_context(config: CliConfig, *, endpoint: str | None, profile: str | None, tenant_id: str | None, environ: Mapping[str, str]) -> ResolvedContext` applies flag/environment/profile precedence.
- `NexaClient.request_json(method: str, path: str, *, query: Mapping[str, object] | None = None, json_body: object | None = None, headers: Mapping[str, str] | None = None, mutation: bool = False, idempotency_key: str | None = None, replayable: bool = True) -> ApiResponse` performs JSON API calls and returns status, decoded body, and response headers.
- `NexaClient.stream_upload(path: str, file: BinaryIO, *, headers: Mapping[str, str], idempotency_key: str) -> ApiResponse` sends a replayable bounded upload body.
- `NexaClient.stream_download(path: str, destination: Path, *, headers: Mapping[str, str], force: bool = False) -> DownloadResult` performs staged bounded download and integrity checks.
- `CliError` carries `exit_code`, safe message, contract code, HTTP status, request ID, and optional retry guidance. `render_error(exc, output_mode) -> str` never renders secrets.
- `emit_success(payload: object, *, mode: OutputMode, human_title: str | None = None) -> None` writes deterministic JSON or human output to stdout.
- `new_idempotency_key() -> str` returns an ASCII-safe cryptographically random key of at least 16 characters.
